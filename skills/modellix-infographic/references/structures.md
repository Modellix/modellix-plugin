# Information structures

Read this when choosing how the source should sit on one image. Offer two or three structures that fit, with a one-line reason for each. Wait for the user to confirm before treating the prompt as ready. A structure the user already named counts as that confirmation.

Use ordinary names. Do not invent a private catalog code.

| Structure | Use it when | Avoid it when |
| --- | --- | --- |
| sequence | The source is ordered: steps, a timeline, a tutorial. | The items do not have an order. |
| comparison | Two or more options share the same facts. | There is only one subject. |
| layers | Importance or depth stacks: surface versus underlying, priority ranks. | The items are peers with no rank. |
| hub | One idea sits in the middle and the others attach to it. | The pieces form a chain or a cycle. |
| cycle | The last step returns to the first. | The process ends. |
| funnel | Volume narrows from many to few. | The counts do not shrink, or the source has no counts. |
| dashboard | The source is a set of named metrics. | The source is a story rather than measures. |
| modules | Several peer topics belong on one overview, each in its own block. | One argument needs a single reading path. |

Pick the structure from the shape of the information, not from a preferred look. A timeline is a sequence even if the user asked for a decorative style. State the visual treatment in a few concrete words inside the prompt, such as flat paper, one accent, or a quiet grid. Keep that treatment consistent across the sections.

If two structures both fit, ask the user which reading path matters more. Do not silently fall back to a favorite.
